# Mod 新增内容图片缺口与复用记录

本文档只记录 **Mod 新增内容** 的图片状态，重点追踪：

- 尚未制作专属图片的新增内容
- 当前临时复用旧图片的新增内容
- 替换专属图片时需要同步调整的代码或资源映射

新增角色、天赋、物品、建筑、建筑动作或机制 UI 时，必须同步检查并更新本文档。已有专属图片且不存在复用的内容不必登记。

## 状态说明

- `待制作`：当前仍在复用旧图，需要制作专属图片。
- `待确认`：扫描发现复用，但是否保留为长期设计尚未确认。
- `已替换`：专属图片已经落地；保留记录，并补充替换提交。
- `有意复用`：确认长期共用，不再视为美术缺口。

## 替换专属图片时的同步清单

### 物品图片

通常需要同时提供：

- `assets/res/icon/icon_item_<itemId>.png`：背包、交易、列表等小图标，当前同类资源画布为 `84×84`。
- `assets/res/dig_item/dig_item_<itemId>.png`：物品详情大图，当前同类资源画布为 `446×264`。

替换后还要检查：

1. `itemConfig.js` 中是否存在 `displayItemId`；已有专属图后应移除临时显示映射。
2. `uiUtil.getDisplayItemId()` 中是否存在硬编码映射；神射手配枪专属图落地后应删除 `1301091 → 1301011`。
3. `icon.plist` / `dig_item.plist` 是否仍让两个资源名指向同一图块。
4. 运行 `node tools/validate-content.js all --lang zh`。
5. 在背包、物品详情、交易列表和奖励弹窗中做视觉检查。

### 建筑动作图片

抽烟专属图已落地，`SmokeBuildAction` 会根据实际动作下标选择 `3` 或 `4`，不再固定使用 `iconIndex: 1`。后续修改抽烟逻辑时，应同时检查椅子、沙发各等级下的动作按钮与进行中提示。

### 天赋图片

新增天赋专属图使用 `assets/res/icon/icon_iap_<purchaseId>.png`，当前同类资源画布为 `169×181`。替换后检查角色/天赋选择弹窗、商店卡片、购买弹窗和成就兑换界面。

## 维护规则

1. 新增 Mod 内容时，先判断是否需要图片；需要但暂未制作时，必须在“当前已确认的临时复用”中登记。
2. 临时复用必须写清：内容 ID、复用对象、图片类型、代码/资源映射位置和计划资源名。
3. 不要只在文案中写“暂时套图”，本文档才是统一追踪入口。
4. 图片替换完成后不要直接删除记录；将状态改为 `已替换`，并注明提交或日期，便于追溯。
5. 如果决定永久共用图片，将状态改为 `有意复用`，并写明设计理由。
